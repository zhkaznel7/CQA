# AI-сервис CQA

Запуск из корня проекта (Node.js 20+, без npm-зависимостей):

```sh
node ai/mock-server.mjs
```

Backend вызывает POST /v1/evaluations с JSON, локально AI_BASE_URL=http://localhost:8001.
Если Backend в Docker, а AI на Mac, используйте http://host.docker.internal:8001.
Порт переопределяется через PORT. Для запроса из файла:

```sh
curl -sS -H 'Content-Type: application/json' --data-binary @ai/mock-request.json http://localhost:8001/v1/evaluations
```

Mock возвращает синтетический ответ на каждый ключ переданной версии. N/A выбирается только при allowNa=true и совпадении с размеченным сценарием из ai/mock-na-fixtures.json. Для сценария общих тарифов совпасть должны канал, весь текст и роли транскрипта, тип, описание критерия и naCondition. Для обрезанного звонка используются стабильный key=01, тип boolean, канал voice call, allowNa=true и системное подтверждение пропущенного начала; положение этого события в массиве может меняться. Поддерживаются формулировка условия из Backend v2 и прежняя формулировка mock. Для других входов mock выдаёт обычную тестовую оценку: для scale первую переданную ступень, для boolean и flag — false. Ключ критерия и номер версии не зашиты. Цитата дословная, индекс начинается с нуля, границы checked_range включительны. Эти данные проверяют транспорт и scoring, для проверки точности нужен реальный evaluator. Backend отвечает за баллы и сохранение.

Для проверки ошибок провайдера запустите процесс с MOCK_ERROR_STATUS=502, 503 или 504. Ошибки JSON и структуры запроса проверяются и без этого режима (400 и 422). Повторов запросов в mock нет. Для smoke-теста новой версии поменяйте id, version, ключ критерия и его шкалу в копии запроса.

По умолчанию bind на 127.0.0.1. Для доступа из контейнера при необходимости задайте HOST=0.0.0.0.

## Оценка через Gemini

Остановите mock перед запуском на том же порту. В zsh введите ключ скрыто:

```zsh
read -rs 'GEMINI_API_KEY?Ключ Gemini: '; echo
export GEMINI_API_KEY
export GEMINI_MODEL=gemini-3.5-flash-lite
node ai/gemini-server.mjs
```

Если node отсутствует в PATH на рабочем Mac, замените node на "$HOME/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node".
GEMINI_MODEL меняет модель (по умолчанию gemini-3.8-flash). Сервис отправляет транскрипт и правила в Google одним запросом на диалог. Лимит ожидания провайдера 90 секунд. Команда curl выше подходит для обоих режимов. Для проверки адаптера без ключа: node --test ai/gemini.test.mjs.

## Проверка версий через Backend

Для живой проверки использована gemini-3.5-flash-lite. В окружении с ключом команда
`node ai/gemini-server.mjs --check-fixture` проверяет исходный диалог отдельно от HTTP.

1. Запустите Gemini-сервис и оцените через Backend диалог из ai/mock-request.json с официальным чек-листом. Сохраните результат: у 01 ожидается false (оператор не представился), у 04 — 0 и заполненный checked_range.
2. Через редактор создайте новую версию: замените описание 01 на «Оператор поздоровался на языке клиента в первом ответе». Сохраните прежний вес и тип, передайте новый снимок и тот же транскрипт.
3. У 01 теперь ожидается true с цитатой «Здравствуйте!». Проверьте идентификаторы версий и наличие обеих оценок в Backend. При расхождении сравните переданное описание и доказательства.

## Применимость N/A в mock

Файл mock-na-fixtures.json содержит два размеченных сценария: исходный вопрос об общих тарифах (N/A для выявления потребности и идентификации) и звонок с явным системным подтверждением пропущенного начала записи (N/A для приветствия). Сам факт voice call или наличие allowNa не подтверждает обрезку записи. Для чата сценарий звонка неприменим.

Mock не интерпретирует произвольный естественный язык. Для дополнительного N/A-сценария добавьте полную размеченную переписку, точное определение критерия и причину в этот JSON и проверьте тестом. Для общего сценария изменённое описание или условие требует новой разметки. Для приветствия изменение описания при том же стабильном ключе поддерживается, но новое условие должно быть эквивалентно одному из явно размеченных naCondition/naConditionAliases. Неизвестное условие не получает N/A автоматически. Семантическую оценку произвольного чек-листа выполняет Gemini. Обычный ответ mock также является синтетическим, поэтому не используйте его для сравнения точности с эталоном.

Backend перед отправкой нормализует speaker в operator/client/bot/system, известные альтернативы сопоставляет явно, неизвестные отклоняет. timestamp в AI-запросе — непустая строка; число можно передать как String(value), для отсутствующего значения предлагается явная строковая метка "unknown". Исходное значение сохраняется в Backend, метка неизвестного времени не считается реальным временем события. Сам mock не интерпретирует время при сопоставлении размеченного сценария.

Проверка без ключа и запросов к Google:

```sh
node --test ai/mock.test.mjs ai/gemini.test.mjs
```

Условие N/A звонка синхронизировано с backend/prisma/seed/call-na-amendment.json ветки backend (8b33b71). Известные варианты в фикстуре заданы явно; это не универсальная проверка семантической эквивалентности естественного языка.

## Изменения оценки после разбора DEV

В версии промпта 2.0.0 внешний HTTP-ответ прежний. Внутри одного вызова Gemini возвращает обзор вопросов клиента и сбоев по всему диалогу, отдельную проверку applicability и доказательства для каждого условия.

- N/A вычисляется из applicability.met при разрешении текущей рубрики. Модель не может одновременно подтвердить условие N/A и выдать обычный ноль в итоговом ответе.
- Для boolean и flag код объединяет проверки через И/ИЛИ и формирует объяснение из этих же проверок. У каждой проверки должны быть обоснование и индексы с дословными цитатами.
- Для scale обязательны все ступени текущей конфигурации, включая неподходящие. Код выбирает максимальную подходящую ступень и использует её обоснование. Исправленная позже неясная инструкция всё равно должна учитываться в оценке всего эпизода.
- Отрицательный флаг грубой ошибки требует диапазона всего диалога. Условия нарушения берутся из рубрики без добавления требования о третьих лицах, согласии клиента или фактической оплате.
- Если необходимая база знаний отсутствует, ограничения добавляются к explanation. Это не новое основание N/A.

Факты применимости, полноту списка атомарных условий и семантику ступеней по-прежнему определяет модель. Код проверяет структуру, происхождение цитат и согласованность сборки ответа, но не доказывает понимание языка моделью. Регрессионные тесты имитируют структурированные ответы; улучшение точности на живой модели требует отдельной проверки. Сохранённые результаты первого прогона автоматически не меняются и не отправляются повторно.
