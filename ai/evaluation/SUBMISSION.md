# Сдача результатов по приложению к гайду, JSON 1.0

В корне репозитория должны быть results/dev/results.json (все 65 DEV-диалогов) и results/prod/results.json (ровно 10 контрольных чатов, включая ошибки). Час после выдачи контроля включает загрузку данных, оценку, проверку, commit и push. Экспорт не отправляет запросы Gemini и сам не делает commit/push.

## Отличия от внутреннего AI API

| Внутренний результат | JSON организаторов |
|---|---|
| 01, 02, 03, 04, 05, 06, 07, 08 | contact, discovery, identification, consultation, empathy, dialogue, closure, critical |
| answer, na=true | value=null |
| explanation и причина N/A | rationale |
| evidence[].turnIndex с нуля | evidence_turns с единицы по всему исходному массиву |
| checked_range включительно | индексы проверенного участка также входят в evidence_turns с единицы |
| Backend score.total | score.final_score |
| Backend score.grossError | score.critical_flag |

AI→Backend контракт сохраняется. При обновлении локальных ключей передайте --criterion-map с JSON-словарём локальный ключ → официальный код. Нужны восемь различных официальных кодов. Для изменения типов/шкал за пределами таблицы приложения потребуется уточнить правила сдачи у организаторов.

## Входы экспортёра

1. --source — неизменённый ответ API организаторов с data.records. По нему проверяются количество, исходные conversation_id и ссылки на реплики.
2. --responses — папка сохранённых ответов AI или JSON-массив таких ответов. ID должны быть исходными из API, включая ошибки.
3. --scores — JSON-массив записей из Backend. Каждая запись имеет conversation_id (исходный ID организаторов), checklist_id и checklist_version из соответствующего AI-ответа и score — полный результат calculateScore. В score нужны total, grossError и criteria с key, value, isNa. Экспортёр сверяет расчёт с ответами AI и версией чек-листа. Итог не вычисляется в ai.
4. --team — точное название команды, --model — фактически использованная модель, --mode — external_api (для Gemini), local или hybrid.

Обёртка scores служит офлайн-передаче сохранённого расчёта; это не изменение HTTP API. Backend UUID диалога нужно сопоставить с conversation_id организаторов до экспорта. Модель можно проверить по manifest прогона, не указывайте модель mock-фикстуры как настоящую Gemini.

## Команда из корня проекта

Замените название команды и пути сохранённых результатов/расчётов на фактические.

```sh
python3 ai/evaluation/export-results.py --dataset dev --source data/dev.json --responses ai/evaluation/predictions --scores backend-scores.json --team 'Название команды' --model gemini-3.5-flash-lite
```

Для контроля:

```sh
python3 ai/evaluation/export-results.py --dataset prod --source data/prod.json --responses prod-predictions --scores prod-backend-scores.json --team 'Название команды' --model gemini-3.5-flash-lite
```

По умолчанию файлы пишутся в требуемые results/dev/results.json и results/prod/results.json. Параметр --output позволяет проверить экспорт во временный путь. UTF-8, schema_version="1.0". Ошибки и отсутствующие результаты оформляются status=error, criteria=[], score=null с причиной. Ни один исходный диалог не исчезает из файла. Успешная запись требует всех восьми допустимых ответов и сохранённого расчёта Backend; без него итог не придумывается.

Экспортёр проверяет цитаты и включительность диапазонов по правилу BUG-004. Для ошибок не копируется произвольное тело ответа провайдера. Не добавляются транскрипты, аудиоссылки и ключи API.

## Подтверждённое исключение для DEV-звонков

2026-11-08 участник команды передал ответ организаторов «ДА» на вопрос, допустимо ли contact.value=null с причиной в rationale для DEV-звонка, у которого начало записи отсутствует и приветствие не попало в запись.

Экспортёр учитывает это уточнение поверх таблицы PDF: для dataset=dev и исходного channel="voice call" разрешён contact=null, если AI вернул na=true с непустым na_reason и сохранённый расчёт Backend соответствует этому N/A. Причина переносится в rationale, доказательства — в evidence_turns с единицы. Итог по-прежнему берётся из Backend с перераспределёнными весами.

Разрешение не означает, что N/A автоматически применим ко всем звонкам: отсутствие начала должно быть подтверждено при оценке и проверено Backend. Экспортёр проверяет форму результата и соответствие сохранённому расчёту, но не устанавливает смысловую достоверность причины по естественному языку. Для чатов, в том числе контрольных, contact остаётся true/false. Для иных критериев набор допустимых значений не меняется.

## Что проверить перед отправкой

Сверить team_name и фактическую модель, количество 65/10, число ok/error и причины ошибок. Подтвердить соответствие версии чек-листа и Backend score исходным ответам. После заполнения необходимо сделать commit и push в ту ветку открытого репозитория, ссылку на которую команда передала организаторам. Локальный JSON или локальный commit сдачей не являются.
