## Контракт запросов и результатов

HTTP-клиент использует `/api` по умолчанию; реальные запросы совпадают с
[Backend API](api.md). Не найдено обращений к выдуманным HTTP endpoints.

- conversationId — Conversation.id; внешний ID показывается через externalId.
- checklistId — UUID выбранной версии, не key или числовой version.
- evaluationId берётся из POST evaluations. При повторе используется тот же результат.
- criterionId для апелляции — results[].criterionId (UUID определения критерия).
  criterionKey и results[].id вместо него не передаются.
- boolean/flag передаются как JSON boolean, ступени как number; scale не пересчитывается
  на Frontend. В UI только форматируются серверные points/total.
- N/A отображается через isNa, а не как false/0. Для CHANGE N/A отправляется
  `{decision:"CHANGE",isNa:true,naReason,reason}` без value и без фактов применимости.
- original score/answer/evidence остаются исходными. После апелляции service.js ищет
  ACCEPTED-апелляцию с нужным evaluationId по страницам и читает её finalScore.
  Это совместимый обход отсутствия отдельного final-evaluation endpoint; новая формула
  или новый Backend endpoint для текущего MVP не требуются.
- evidence.turnIndex и checkedRange включительны, от 0 по полному транскрипту.
  UI показывает номер +1, но фокусирует исходную позицию, включая system/client.
  Поле raw AI checked_range не путается с публичным checkedRange.
- Backend сохраняет audio_url источника как audioUrl; Frontend читает именно audioUrl.
  Синтетическая ссылка получена неизменённой, проверены HTTP 200/audio-wav и DOM fallback.

## Подтверждённые проблемы и владельцы исправлений

### P1: T02 отсутствует в интерфейсе — Frontend

`ConversationList.vue:8` вызывает `/conversations?page=...` без group_id, не показывает
groupId, не содержит выбора группы/импорта. В двух тестовых группах один externalId
возвращает две разные записи, но пользователь не видит принадлежность. Это не ошибка
API: GET с group_id возвращает только нужную группу.

Нужно добавить ввод выданного group_id, POST `/conversations/import` с `{group_id}`,
обновление списка и фильтрацию GET; показывать groupId. При изменении группы сбрасывать
page=1. PagedList сейчас всегда добавляет `?page=...`: передача path уже с query создаст
некорректный URL. Строить query через URLSearchParams либо поддержать отдельные props
фильтров. Реальный контрольный ID и PROD-набор здесь не создавались.

### P1: legacy COMPLETED со score=null ломает панель — Frontend

Воспроизведение на отдельной фикстуре: старая COMPLETED-оценка без AI/scoring snapshot;
POST evaluations возвращает HTTP 200, reused=true, data.score=null. Открыть диалог,
выбрать её версию, нажать «Оценить». В EvaluationPanel.vue есть незащищённые обращения
`evaluation.score.criteria` (стр. 51), `.sections` (стр. 62), total/grossError в шаблоне.
Зафиксирована ошибка render с null, вместо понятного состояния интерфейса.

Нужно проверять наличие совместимого score/results до рендера, показывать сообщение о
старом формате и отключать неподдерживаемые действия. Не заменять null на 0 или N/A,
не запускать повторный AI автоматически и не менять старые оценки ради интерфейса.
Backend сохраняет совместимость истории намеренно; исправление Backend не требуется.

### Ограничение аудио — Frontend + данные организаторов

Во всех 5 DEV-звонках есть audio_url; у 386 реплик этих звонков нет пары startMs/endMs.
recording.js использует именно эту пару для привязки к записи, поэтому возвращает
пустые turns/findings для такого источника. Текстовое evidence работает; точный seek
по доказательству на реальных DEV-звонках не подтверждён. Нельзя выдумывать смещения
или менять исходные timestamp. Нужны надёжная привязка от организаторов и явное сообщение
UI о недоступной временной разметке. Waveform загрузка также зависит от CORS/формата/
срока действия ссылки у владельца записи; браузерный fallback и исходная ссылка имеются.

### Неполный редактор секций — Frontend, ниже приоритет

Существующие sections/instructions сохраняются, критерий можно переместить в существующую
секцию. Но добавить/переименовать секции и редактировать инструкции через UI нельзя.
Backend уже поддерживает эти поля; решается формой, не изменением схемы Backend.

## CORS, сеть и команды

Проверены реальные Vite dev server и работающий Docker Backend, без записи в основную БД:

| Проверка | HTTP |
| --- | --- |
| HTML Frontend | 200 |
| Vite `/api/health` → Backend | 200 |
| Backend с Origin http://localhost:5173 | 200, разрешённый origin |
| Backend с Origin http://127.0.0.1:5173 | 403 CORS_ORIGIN_DENIED |
| OPTIONS для PATCH с localhost:5173/content-type | 204, PATCH разрешён |
| Ошибочная база API без /api, запрос /conversations | 404 NOT_FOUND |

Рабочая разработка после согласованного объединения (не выполнялась в основном frontend):

```powershell
Set-Location C:\Users\zhanel\CQA\frontend
npm.cmd ci
$env:CQA_BACKEND_URL = 'http://127.0.0.1:3000'
npm.cmd run dev -- --host localhost
# Открыть http://localhost:5173/#/dialogs
```

Для отдельной статической сборки:

```powershell
$env:VITE_API_BASE_URL = 'http://127.0.0.1:3000/api'
npm.cmd run build
```

VITE_API_BASE_URL должен включать `/api`; переменная встраивается при build.
Вариант с одним origin и reverse proxy `/api` тоже совместим. Для другого адреса/порта
Frontend администратор добавляет его точный origin в backend CORS_ORIGINS и обновляет
Backend-контейнер. Изменять бизнес-логику CORS или разрешать все origins не нужно.
Файл .env и секреты организаторов никогда не передаются Frontend.

## Рекомендуемый порядок объединения

1. Автор Frontend исправляет P1 группы и legacy, добавляет регрессии. Согласовать
   ограничения аудио/секций и конфигурацию origin/API base.
2. Повторить Frontend unit/build и адресные сценарии на отдельной БД по новому commit.
3. После отдельного разрешения объединять origin/frontend в текущий backend, где AI
   уже объединён. Не заменять папки Backend/AI содержимым старой Frontend-ветки.
4. Для проверенных commit пересечений изменённых путей относительно общего предка
   `7f921f4` нет (Frontend 38, Backend 141). Это анализ diff, не выполненный merge.
5. После фактического merge запустить Backend/AI/Frontend тесты и браузерный smoke со
   всеми сервисами. Затем отдельно решать commit/push; автоматических Git-операций нет.
