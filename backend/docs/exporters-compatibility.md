# Единый экспорт официальных результатов

Дата: 8 ноября 2026. Рекомендация: **единственным производителем официального
results.json оставить Backend `npm.cmd run export:results`**. Он читает выбранную
версию и сохранённые результаты PostgreSQL, проверяет соответствие calculateScore,
применимость N/A и защищает файл от перезаписи. Scoring Engine не изменялся.

AI-экспортёр сравнён из неизменённого снимка `origin/codex/ai-mock`, commit
`0789aaf82de8559d7a36707161619acdf5a25031`, файл `ai/evaluation/export-results.py`.
В рабочей ветке этого файла пока нет. Для изучения выполнен fetch, без merge/checkout.
Снимок расположен только в игнорируемой backend/.tmp; файлы AI не менялись.

## Входы и единый источник истины

| Данные | Backend | AI-экспортёр |
| --- | --- | --- |
| Исходный набор | --input: официальный ответ API, isSuccess и total_records проверяются | --source: data.records, размер и ID проверяются; isSuccess/total_records не проверяются |
| Результаты | Выборка Evaluation/criterion results из БД по --checklist UUID и исходным ID manifest | --responses: массив JSON или каталог отдельных ответов |
| Баллы | Сохранённый Evaluation.score; existing calculateScore используется для сверки | --scores: массив сохранённых расчётов; собственная формула отсутствует |
| ID диалога | В БД и AI HTTP — UUID; наружу — Conversation.externalId | Во всех внешних файлах нужен исходный conversation_id |
| Версия | Проверяется выбранный Checklist и сохранённый AI snapshot | Проверяются checklist_id/version ответа и обёртки score |
| Выход | Атомарный UTF-8 JSON 1.0, существующий файл не перезаписывается | UTF-8 JSON 1.0; существующий output заменяется |

Прямой GET /api/evaluations/:id не является готовым --scores: у него обёртка data,
camelCase, внутренний UUID и другой состав полей. Нельзя заменять сохранённые баллы
расчётом в AI или вручную подставлять final_score.

Backend получил опциональный `--ai-input-dir`: из одного read-only RepeatableRead
снимка создаются три файла. Сам официальный результат по-прежнему создаётся одним
механизмом Backend; пакет нужен только для офлайн-сверки и передачи AI-разработчику.

**responses.json** — массив исходных aiResponse, у которых только верхний
conversation_id заменён на исходный externalId. В БД оригинал не обновляется.

**backend-scores.json** — массив объектов:

| Поле | Тип и источник |
| --- | --- |
| conversation_id | string, Conversation.externalId |
| checklist_id | UUID string, выбранный Checklist.id |
| checklist_version | integer, выбранный Checklist.version |
| score | полный неизменённый Evaluation.score, включая total, grossError, criteria, sections и scoringVersion |

В score.criteria остаются внутренние key `01`–`08`, value и isNa. Обёртка и raw AI
snapshot сверяются по ID/версии; typed answers, объяснения, причины N/A, evidence и
checked_range должны совпадать с сохранёнными строками. Новые баллы не вычисляются
мостом. manifest.json фиксирует dataset, checklist ID/version, model/team, synthetic,
соответствие внешнего ID UUID/ID оценки и статус каждого диалога.

В официальный JSON 1.0 не добавляются поля checklist_id/checklist_version, которых
нет в приложении PDF: версия проверяется до экспорта и сохраняется в пакете передачи.

Для error Backend-пакет сохраняет conversation_id в responses с безопасным кодом
BACKEND_EXPORT_ERROR, не передаёт фиктивный score и хранит причину в manifest.
AI затем тоже выдаёт status=error, criteria=[], score=null. Тексты error у двух
экспортёров могут различаться; статус, ID и отсутствие балла совпадают.

Каталог пакета должен быть новым и находиться в backend/.tmp. Файлы не попадают в Git.
В AI передаются конкретные responses.json/backend-scores.json, не весь каталог:
иначе AI прочитает manifest и scores как ответы и обнаружит неправильные/дублирующиеся ID.

## Подтверждённые различия и исправления Backend

1. **contact=null.** PDF на стр. 3 задаёт boolean; последнее уточнение организаторов,
   переданное пользователем 8 ноября, разрешает исключение для обрезанных DEV-звонков.
   Прежний Backend всегда делал error. Теперь исключение допускается только при
   dataset=dev, call-канале, явном recording_start_missing и независимом подтверждении
   именно выбранной версии. Чат/PROD/неподтверждённый случай не получает null.
2. **rationale для N/A.** Раньше Backend добавлял explanation + "N/A: reason", AI —
   reason + explanation. Backend согласован с AI: причина впереди, затем объяснение,
   без дублирования при равенстве после trim. Сохранённые строки не меняются.
3. **evidence_turns.** AI разворачивает любой explicit checked_range; прежний Backend —
   только пропущенный boolean или случай без цитат. Backend теперь также включает все
   проверенные интервалы: start/end включительны, каждый индекс +1, union без повторов.
   Клиент, bot и system сохраняют исходные позиции.
4. **Legacy/DRAFT и неизвестная provenance.** Не должны прерывать экспорт и терять ID:
   Backend теперь сохраняет соответствующую error-запись без нулевого балла.
5. **Raw snapshot / версия.** Backend дополнительно сверяет aiResponse с сохранёнными
   criterion rows и выбранной версией; противоречивый snapshot не экспортируется как ok.
6. **Контекст contact=null.** AI разрешает его только при точной строке source.channel
   "voice call". Backend корректно поддерживает и voice/call (BUG-003). Это оставшееся
   различие AI-инструмента; официальный DEV использует voice call, поэтому все 65
   стандартных записей совместимы. Не нужно ослаблять Backend или переписывать source.
7. **Доверие --scores.** AI проверяет форму и совпадение ответов, но не может проверить
   независимый факт в БД и не пересчитывает total. На синтетических некорректных входах
   без подтверждения или с подменённым total=99 он принимает данные, которые Backend
   отклоняет. Это граница доверия офлайн-файлу, не причина добавлять второй Scoring Engine.
   Backend-пакет заранее превращает такие случаи в error и устраняет различие статусов.
8. **Другие ограничения.** AI допускает явный --criterion-map для переименованных ключей;
   Backend пока экспортирует только стандартные 01–08 с официальными типами/весами/шкалами.
   Для стандартной сдачи mapping одинаков. AI не защищает от маркировки mock названием
   Gemini и может перезаписать старый файл; Backend запрещает это и остаётся основным.

## Фактическая проверка

- Источник: все 65 настоящих DEV-записей, сохранённые **mock**-оценки из отдельной БД
  cqa_audit_test_1794080119448. Повторная генерация оценок для сравнения не требовалась:
  обоим экспортёрам даны одни и те же сохранённые ответы и Backend score.
- AI-экспортёр выполнен в временном Python 3.13-контейнере с --network none и readonly
  кодом. Gemini не запускался. Метаданные обоих файлов: local, CQA mock (synthetic; not
  Gemini), AUDIT SYNTHETIC NOT FOR SUBMISSION.
- **65 Backend ok, 65 AI ok, 0 различных диалогов**. Сравнены полные разобранные JSON,
  включая метаданные, порядок, все критерии, rationale, evidence_turns и итоговые баллы.
  На стандартных 65 mock-записях совпадение было и до изменений — там нет contact=N/A;
  несовместимости проявлялись на отдельных крайних сценариях.
- Новый документированный CLI создал основной mock-файл и --ai-input-dir; Python
  прочитал эти конкретные файлы. Полные выходные JSON снова совпали для всех 65,
  включая побайтовое сравнение файлов. Повторное чтение БД подтвердило: исходные
  score, AI-ответы, channel и транскрипты всех 65 оценок не изменились.
- **18 тестов Backend-экспорта прошли**. Полный регрессионный набор: **134 passed,
  0 failed, 0 skipped**. Это регрессии, повторный технический аудит не проводился.
- **10 штатных тестов AI-экспортёра** commit 0789aaf прошли без изменений.
- Девять дополнительных **синтетических строковых** сравнений: подтверждённый DEV
  N/A=38.89, чат, отсутствие подтверждения, подмена total, неверная версия, отсутствие
  оценки, ложная цитата, range для положительного/scale-ответа и voice-алиас.
  После Backend-пакета совпали смысловые результаты 8/9; оставшийся — voice-алиас AI.
  На error сравнивались ID/status/criteria/score; тексты причин не объявляются идентичными.

PROD-набор и файлы сдачи не создавались. Все результаты сравнения находятся в
backend/.tmp/export-compat-1794081903651 и не публикуются. Снимок AI проверен SHA-256,
AI/Frontend/Scoring Engine не менялись. Существующие результаты и базы не удалялись.

## Что должен сделать AI-разработчик

1. Согласовать Backend как единственного производителя официального results.json;
   AI-экспортёр оставить тестовым проверяющим/офлайн-инструментом, убрать автоматическую
   запись в пути сдачи из AI-процесса. Эти изменения AI здесь не выполнялись.
2. При сравнении читать конкретные responses.json и backend-scores.json, учитывать
   manifest.synthetic/model и не маркировать mock как Gemini. Не редактировать score.
3. Если нужна совместимость с legacy-алиасами, разрешить известные voice/call вместе с
   voice call в DEV-исключении; не разрешать чаты и не делать собственную формулу балла.
4. Для нового criterion-map или изменённой контрольной схемы согласовать отображение
   отдельно; не выводить официальный criterion_id из позиции произвольно.
5. При передаче уже error-пакета сохранять ID/error и не пытаться восстанавливать балл.

## Команда основного экспорта

```powershell
Set-Location C:\Users\zhanel\CQA\backend
$checklistId = Read-Host 'UUID сохранённой версии чек-листа'
# Настоящие результаты — только с фактическими именами команды/модели:
npm.cmd run export:results -- --dataset dev --input ../data/dev.json --checklist $checklistId --team 'ИМЯ_КОМАНДЫ' --model-name 'ФАКТИЧЕСКАЯ_МОДЕЛЬ' --model-mode external_api
# Проверка на mock с новым именем файла/каталога:
npm.cmd run export:results -- --dataset dev --input ../data/dev.json --checklist $checklistId --team 'AUDIT SYNTHETIC NOT FOR SUBMISSION' --allow-mock --output .tmp/compare-new.mock.json --ai-input-dir .tmp/ai-inputs-new
node --test tests/export-results.test.js
```

Официальный файл формирует только Backend. Пакет не требует Python в production и
не меняет HTTP-контракт AI или внутренние UUID в PostgreSQL.

## Оставшиеся блокеры

Для стандартного DEV экспортёры совместимы; Backend можно использовать основным.
Самостоятельный AI-export ещё требует указанного согласования роли и алиасов.
Для официальной сдачи по-прежнему нужны реальные результаты выбранной модели,
фактические имена команды/модели, настоящий PROD и проверка разрешённого момента
публикации. Synthetic-совпадение не доказывает точность модели. Commit/push/merge
не выполнялись; код AI не менялся и не переносился в рабочую ai/.
