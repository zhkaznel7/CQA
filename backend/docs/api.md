# API этапа 3

Все идентификаторы маршрутов — внутренние UUID. ID организаторов хранится в externalId.
Успешная отдельная запись: `{ "data": { ... } }`.
Списки: `{ "data": [...], "pagination": { "page": 1, "pageSize": 20, "total": 3, "totalPages": 1 } }`.
Ошибка: `{ "error": { "code": "...", "message": "...", "details": [...] } }`.
Details в ошибках валидации содержит только пути полей и коды, без входных значений.

| Метод и маршрут | Поведение | Успех |
| --- | --- | --- |
| GET /api/health | Прежний healthcheck | 200 |
| GET /api/conversations | Метаданные без транскрипта | 200 |
| GET /api/conversations/:id | Диалог с исходным транскриптом | 200 |
| POST /api/conversations/import | Импорт из настроенного серверного источника | 200 |
| GET /api/checklists | Все версии чек-листов | 200 |
| GET /api/checklists/:id | Конкретная версия с критериями | 200 |
| POST /api/checklists | Новый ключ, версия 1 | 201 |
| PUT /api/checklists/:id | Полная новая версия существующего ключа | 201 |
| POST /api/evaluations | Оценить через AI/mock, проверить, рассчитать и сохранить | 201 / 200 повтор |
| GET /api/evaluations/:id | Сохранённый результат с исходными ответами и scoring snapshot | 200 |

| PATCH /api/appeals/:id/decision | CONFIRM/CHANGE с обязательной reason | 200 |

Контракт пересмотра: [appeals.md](appeals.md). criterionId — UUID ChecklistCriterion
из результатов оценки, не key и не UUID CriterionResult.

Контракт AI, Evaluations API и правила независимого подтверждения N/A:

приветствия только в соответствующей новой версии, не в исходном PDF-чек-листе.

## Диалоги

Параметры списка: page (1–100000, default 1), pageSize (1–100, default 20),
language (RU/KZ/EN) и channel (точная строка до 50 символов). Неизвестные параметры
отклоняются. Порядок: createdAt DESC, id DESC, со стабильным разрешением совпавших дат.

Импорт принимает пустое JSON-тело `{}` или отсутствие тела. URL, токен, conversations
и любые другие поля запроса запрещены. По умолчанию источник — синтетический mock.
Для API организаторов используется только URL из окружения, без пользовательского ввода
и переходов по redirects. Токен передаётся в Authorization: Bearer.
Настроенный URL — доверенная настройка оператора развёртывания, а не поле HTTP API.

Контракт источника (пока реальный формат организаторов не предоставлен):

```json
{
  "conversations": [
    {
      "externalId": "synthetic-001",
      "language": "RU",
      "channel": "chat",
      "audioUrl": null,
      "transcript": [
        { "speaker": "operator", "text": "Тестовый диалог", "timestamp": "00:00:01.250" }
      ]
    }
  ]
}
```

Адаптация другого формата источника выполняется в organizer-client.js. Backend не скачивает
audioUrl и другие URL внутри записей. Timestamp может быть строкой или неотрицательным
числом; timestamp/startMs/endMs сохраняются без преобразования. Дополнительные поля реплик
также сохраняются. Массив не сортируется. Для каждой реплики добавляется turnIndex = позиция
с нуля; если источник уже указал turnIndex, он обязан совпадать с этой позицией.
Другие исходные поля индекса, например originalIndex, не изменяются.

По умолчанию максимум 500 записей и 2 MB на ответ источника, timeout 10 секунд.
Пустой список корректен. Пустой ID, неподдерживаемый язык, пустой транскрипт, пустая
реплика или неправильный turnIndex отклоняют только соответствующую запись.
В пределах пачки побеждает первая валидная запись с externalId; существующие записи
не изменяются. Параллельные импорты защищает UNIQUE + ON CONFLICT DO NOTHING.
Один вызов createMany атомарен: ошибка БД не оставляет частично записанную пачку.

```json
{
  "data": {
    "received": 5, "imported": 2, "duplicates": 2, "invalid": 1,
    "rejected": [{ "index": 4, "code": "INVALID_RECORD", "paths": ["language"] }]
  }
}
```

Даже если все записи некорректны, возвращается 200 с invalid/rejected и imported=0.
Некорректная оболочка ответа источника или превышение лимитов — 502.

## Чек-листы

Список поддерживает page/pageSize и key; возвращаются все версии, не только последняя.
GET по UUID возвращает именно эту версию, критерии — в сохранённом порядке.

Минимальная пользовательская конфигурация POST:

```json
{
  "key": "synthetic-example",
  "name": "Тестовый чек-лист",
  "sections": [{ "key": "main", "name": "Тестовая секция" }],
  "criteria": [
    {
      "key": "example", "name": "Тестовый критерий", "description": "Синтетическое описание.",
      "type": "boolean", "weight": 100, "sectionKey": "main", "allowNa": false
    },
    {
      "key": "violation", "name": "Тестовый флаг", "description": "Синтетический флаг.",
      "type": "flag", "weight": 0, "sectionKey": "main", "allowNa": false
    }
  ],
  "instructions": []
}
```

PUT принимает такую же полную конфигурацию **без key**; key и номер версии сервер
определяет сам. criteria заменяет весь набор в новой версии, поэтому можно добавлять,
удалять и заменять критерии без изменения кода. Названия и описания не обрезаются и
не переформулируются. Неизвестные поля запрещены. Поля ответа id/version/createdAt,
maxPoints/schemaVersion/position не нужно отправлять обратно в тело запроса.

Правила:

- От 1 до 100 критериев, 1–30 секций; ключи критериев и секций уникальны.
- Каждый критерий ссылается на существующий sectionKey.
- boolean: положительный вес, maxPoints=1, без scaleSteps.
- scale: положительный вес, scaleSteps из 2–50 `{value,label}`; значения уникальны,
  строго возрастают либо убывают и включают 0. Порядок сохраняется, максимум определяется
  по наибольшему значению. Допустимо до четырёх знаков после запятой.
- flag: weight=0, maxPoints=0, без шкалы и N/A. Флаг не участвует в сумме весов.
- Сумма весов всех обычных критериев — 100; вес до двух знаков после запятой.
- allowNa=true требует непустую naCondition; при false naCondition=null.
- instructions хранит текст требований; выражения naCondition не исполняются как код.

Официальная конфигурация содержит ровно 8 критериев. Пользовательские версии могут
иметь другое количество критериев при соблюдении правил выше.
Транзакция и advisory lock по key сериализуют создание версий; UNIQUE(key,version)
страхует целостность. Создание от устаревшего UUID возвращает 409: сначала загрузите
последнюю версию. Старые версии, их критерии и связанные оценки не изменяются.

## Ошибки

| Статус | Причина |
| --- | --- |
| 400 | Ошибка Zod, неизвестные поля, некорректный UUID/JSON/конфигурация |
| 403 | Origin не разрешён CORS |
| 404 | Диалог или версия не найдены |
| 409 | Повтор ключа, устаревшая версия, конфликт изменений |
| 413 | JSON запроса превышает лимит |
| 429 | Превышен rate limit |
| 502 | Ошибка источника, redirect, невалидный JSON/оболочка, превышение размера |
| 503 | Источник не настроен или БД недоступна |
| 504 | Timeout внешнего API |
| 500 | Неожиданная внутренняя ошибка без приватных деталей |
