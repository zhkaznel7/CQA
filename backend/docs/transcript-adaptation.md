# Безопасная адаптация timestamp и speaker для AI

## Проверенный источник

Проверен доступный локальный файл организаторского DEV-набора `data/dev.json`:
оболочка `{error,isSuccess,data:{dataset_group_id,total_records,records:[...]}}`.
В нём 65 диалогов (60 agent chat, 5 voice call), 1268 реплик.
Тексты клиентов не выводились в отчёт и не отправлялись AI; анализировались только
структура, типы и агрегированная статистика.

| Поле | Реальные форматы DEV |
| --- | --- |
| timestamp | 1268 строк: 882 MM:SS, 386 ISO с 7 знаками дробной секунды и часовым смещением |
| speaker | client: 505, bot: 315, system: 109, operator: 339 |

У Backend контракт импорта шире: timestamp/startMs могут быть строкой либо
неотрицательным числом и могут отсутствовать; speaker раньше допускал произвольную
непустую строку. Это объясняет несовместимости синтетических и иных данных с AI mock,
который требует строковое время и operator/client/system/bot.
Новый код не меняет формат импорта, не импортирует весь DEV-файл и не изменяет
существующие записи. API организаторов при этой проверке не вызывался.

## Правила перед HTTP-вызовом

`src/ai-client/transcript-adapter.js` создаёт отдельный массив запроса:

- Непустой строковый timestamp передаётся **без изменений**, включая ISO с точностью
  7 знаков и исходный offset. Date, парсинг/переформатирование и округление не используются.
- Конечное неотрицательное число переводится через String: `1250 → "1250"`, `0 → "0"`,
  `1.25 → "1.25"`. Единицы не угадываются и не пересчитываются. Небезопасные целые числа
  вне диапазона точного Number отклоняются, а не считаются точными временными значениями.
- Если timestamp=null/отсутствует, можно использовать **реально существующий** startMs
  по тем же правилам. Это чтение исходного значения, не генерация отсутствующего времени.
- Если нет обоих источников, Backend возвращает **422 AI_TIMESTAMP_REQUIRED до HTTP**.
  Время не подставляется из соседней реплики, endMs, текущей даты, индекса или "00:00".
- Пустое/невалидное переданное время не заменяется молча другим источником:
  **422 AI_TIMESTAMP_INVALID**. Boolean, массив, объект, NaN/Infinity и отрицательные
  значения не превращаются в строки.
- Разрешены только подтверждённые роли operator/client/system/bot. Для этих имён
  допускается нормализация регистра и внешних пробелов (`" OPERATOR " → "operator"`).
- agent/customer/оператор/числовые ID/произвольные имена не переименовываются:
  **422 AI_SPEAKER_UNSUPPORTED до HTTP**. Роль не выводится из текста или языка.
- Текст, порядок и turnIndex сохраняются; реплики не сортируются и не пропускаются.
  Если явный turnIndex противоречит позиции, применяется прежний INVALID_TRANSCRIPT.
- Ошибки содержат только номер реплики и имя поля, без исходного текста/неизвестной роли.

Например, PostgreSQL сохраняет:

```json
{ "speaker": " OPERATOR ", "timestamp": 1250, "text": "Synthetic example" }
```

AI получает:

```json
{ "turnIndex": 0, "speaker": "operator", "timestamp": "1250", "text": "Synthetic example" }
```

GET диалога по-прежнему возвращает исходные число и строку роли. Адаптер не выполняет
UPDATE и не перезаписывает исторические AI-ответы/доказательства.

## Защита от изменений во время AI-запроса

Проверка перед сохранением теперь сравнивает исходные transcript/channel/language,
а не только нормализованный AI-запрос. Изменение `1250 → "1250"` или
`" OPERATOR " → "operator"` другим процессом во время вызова не маскируется адаптацией:
возвращается **409 EVALUATION_INPUT_CHANGED**, оценка не сохраняется.
