## Запуск AI mock

Инструкция ветки: ai/README.md. Зависимости: только стандартные модули Node.js,
достаточно Node.js 20+; npm install и Docker не нужны.

```powershell
node ai/mock-server.mjs
```

По умолчанию HOST=127.0.0.1, PORT=8001. Endpoint — POST /v1/evaluations,
Content-Type application/json. Mock импортирует только ai/http.mjs и не вызывает
Gemini или другие внешние/платные API. Gemini-файлы из ветки не запускались.
MOCK_ERROR_STATUS=502/503/504 — поддержанные симуляции ошибок сервиса.

Во время проверки mock действительно работал на 127.0.0.1:8001 отдельным процессом.
Обычный Backend запускался через npm start на 127.0.0.1:3000 с:

```text
AI_MODE=http
AI_BASE_URL=http://127.0.0.1:8001
AI_SERVICE_KIND=mock
```

## Конкретные несовместимости

### 1. channel — исправлено на границе Backend → AI

ai/http.mjs принимает только **agent chat / voice call**. Раньше Backend отправлял
сохранённые **chat / voice / call** без преобразования. Реальные запросы с voice и chat
получили AI 422 INVALID_CONVERSATION, Backend 502 AI_HTTP_ERROR.

Добавлено только отображение wire-значения:

| Backend channel | AI channel |
| --- | --- |
| chat или agent chat | agent chat |
| voice, call или voice call | voice call |

Канал в БД и исходный объект не изменяются. N/A проверяется по исходному каналу и
правилу сохранённой версии. Неизвестные каналы не угадываются и не превращаются в chat.
Wire-словарь не означает автоматического изменения доменных правил/данных импорта.

### 2. transcript[].timestamp — остаётся несовместимость

- Ожидание текущего AI mock: только непустая **строка** (`hasText(t.timestamp)`).
- Backend поддерживает исходные строки, числа и неизвестное время. Например,
  timestamp=1250 или отсутствующие timestamp/startMs → wire timestamp=null.
- Фактически AI отвечает **422 INVALID_TRANSCRIPT**, Backend — **502 AI_HTTP_ERROR**.

Нужное исправление/решение AI-команды: согласовать поддержку исходных числовых/null
значений либо единый явный формат и единицы времени. Backend не превращает 1250 в
выдуманную дату/секунды и не дописывает отсутствующее время. Хранимые timestamp сохранены.
Положительные HTTP-проверки выполнялись с исходными строковыми timestamp.

### 3. N/A — тип совместим, выбор mock не соответствует проверке применимости

В ai/mock-server.mjs буквально используется `const na = c.allowNa`.
allowNa означает разрешённый вариант ответа, а не подтверждённое выполнение условия.
По официальному v1 mock всегда возвращает N/A для 02/03/04/07. Без независимых фактов
Backend возвращает **502 AI_NA_UNCONFIRMED**, не создавая Evaluation.

Для положительных тестовых сценариев заранее созданы явно синтетические, независимо
подтверждённые фикстуры ApplicabilityConfirmation. Это не автоматическое подтверждение
N/A и не проверка качества реальных разговоров. Подтверждения привязаны к конкретному
диалогу, версии и критерию; факты v1 не разрешают N/A в v2.

Нужное исправление mock: отдельные управляемые сценарии выбора N/A для конкретных
фикстур, обычный применимый ответ по умолчанию. Проверку Backend ослаблять нельзя.

### 4. Приветствие в чате — остаётся поведенческое расхождение mock

В версии с правилом recording_start_missing ожидается:
канал voice/call **и** независимый факт отсутствующего начала записи. Chat запрещён.
Mock игнорирует channel/naCondition и при allowNa=true возвращает:

```json
{ "criterion_id": "01", "answer": null, "na": true }
```

Это воспроизведено на chat даже при наличии синтетической строки подтверждения:
Backend правильно вернул 502 AI_NA_UNCONFIRMED. В звонке без нужного факта — тот же
отказ; с явным правилом версии и фактом — 201 и итог 50 на синтетической фикстуре.
AI mock должен выбирать N/A только в явно заданном допустимом сценарии, не для всех
звонков или всех критериев с allowNa=true.

### 5. transcript[].speaker — различаются допустимые множества

AI принимает только operator/client/system/bot. Backend import допускает непустую
строку; пример допустимого Backend speaker=agent получил AI 422 INVALID_TRANSCRIPT.
Нужно согласовать словарь ролей с источником и явные известные alias. Слепого
переименования неизвестной роли в operator не добавлено.

### 6. Статусы ошибок AI — исправлено в Backend

Ранее любой ответ не-2xx, включая командные MOCK_ERROR_STATUS=503/504, становился
Backend 502 AI_HTTP_ERROR. Теперь реальные HTTP ответы командного mock дают:

| AI HTTP | Backend HTTP / code |
| --- | --- |
| 502 | 502 / AI_HTTP_ERROR |
| 503 | 503 / AI_UNAVAILABLE |
| 504 | 504 / AI_TIMEOUT |

Ответы провайдера и возможные секреты не копируются в клиентское сообщение.
Сетевой отказ остаётся 503, срабатывание таймера — 504.

### Примечание к ai/mock-request.json

Пример использует conversation_id="mock-ru-001", а Backend оперирует UUID PostgreSQL.
Такой standalone curl — допустим для AI mock, но его ответ не является валидным
Backend-снимком с UUID. Реальные Backend-запросы передают UUID и проходят проверку.
Для общей интеграционной фикстуры AI-команде стоит использовать UUID, не внешний ID.

## Реальные HTTP и DB результаты

Выполнено **30 проверок: 30 соответствуют ожидаемому результату, 0 неожиданных падений**.
В этот счёт входят воспроизведённые несовместимости/ожидаемые отказы, поэтому 30/30
не следует интерпретировать как полную совместимость.

- Backend → неизменённый командный mock на 8001 → проверка → scoring → PostgreSQL:
  HTTP 201, provider=mock, transport=http, isMock=true.
- RU/KZ/EN со строковым временем и подтверждёнными синтетическими N/A: итог **37.5**.
- GET вернул тот же aiResponse, точные цитаты, checked_range и scoring snapshot.
- Повтор POST вернул 200/reused=true, без перезаписи.
- Новая версия: 01 изменён с boolean на scale [4,2,0]; mock вернул 4,
  Backend сохранил итог **62.5**. Исходная версия сохранила **37.5**.
- Пользовательский чек-лист с тремя произвольными keys и boolean/scale/flag дал итог **80**.
- Недопустимые ответы не оставили частичных Evaluation в БД.

Отдельный тестовый HTTP proxy (не изменение AI-кода) проверил:

| Симуляция | Backend |
| --- | --- |
| Некорректный JSON | 502 AI_INVALID_JSON |
| Отсутствующий критерий | 502 AI_CRITERIA_MISMATCH |
| Недопустимая ступень | 502 AI_INVALID_ANSWER |
| Ложная цитата / неверный индекс | 502 AI_INVALID_EVIDENCE |
| Диапазон вне транскрипта | 502 AI_INVALID_RANGE |
| Запрещённый N/A | 502 AI_NA_UNCONFIRMED |
| Timeout | 504 AI_TIMEOUT |
| Остановленный HTTP-сервис | 503 AI_UNAVAILABLE |

Для timeout использован сокращённый тестовый лимит 150 ms; стандартный timeout
Backend не изменён (100000 ms). Ошибки 502/503/504 дополнительно проверены собственным
MOCK_ERROR_STATUS неизменённого командного сервиса на временных портах.

