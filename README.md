# CQA · Контроль качества диалогов

Прототип команды **Heroes** для хакатона Freedom Broker. Аналитик оценивает чаты и звонки на русском, казахском и английском, переходит к доказательствам в транскрипте и оспаривает отдельные критерии. Проверяющий видит исходную оценку, фиксирует решение и получает пересчитанный итог.

## Запуск

Установите Docker Desktop с Docker Compose и запустите Docker. Откройте терминал в папке проекта и выполните

```powershell
docker compose up -d --build
```

Откройте **[CQA на localhost:5174](http://localhost:5174/)**. Проверка сервера доступна по адресу [localhost:3001/api/health](http://localhost:3001/api/health). При первом запуске сервер создаёт таблицы PostgreSQL и начальную версию чек-листа. База хранится в именованном томе Docker. Остановить приложение с сохранением данных можно командой `docker compose down`.

На этом компьютере адрес GET из PDF уже настроен в локальном файле `.env`. Для переноса на другую машину скопируйте `.env.example` в `.env`, задайте свой пароль до первого запуска базы. Для доступа к API укажите `IMPORT_SOURCE=organizers` и полный адрес кнопки **«Открыть GET для DEV»** в `ORGANIZER_API_URL`. Сервер подставит выбранный `group_id`. Локальный файл с адресом и ключами исключён из Git. Без настройки API доступны демонстрационные записи и загрузка исходного JSON через браузер.

## Как провести проверку

1. В разделе **Наборы данных** загрузите группу `DEV` через API или выберите JSON с исходным ответом организаторов. При повторном импорте существующие диалоги сохраняют свои идентификаторы и историю.
2. В разделе **Диалоги** откройте карточку, выберите версию чек-листа и запустите оценку. Разверните критерий и нажмите на реплику-доказательство. У звонка с доступной записью можно открыть плеер.
3. Из результата подайте апелляцию на конкретный критерий и укажите причину. В разделе **Апелляции** откройте обращение, сохраните подтверждение или новое значение с объяснением. В карточке обращения будут видны исходный и окончательный баллы.
4. В разделе **Чек-листы** измените критерий и сохраните новую версию. Примените её в карточке того же диалога. Старые оценки остаются привязаны к своей версии.

Чтобы повторить проверку через API, откройте диалог с готовой оценкой. В блоке результата нажмите **Удалить оценку** и подтвердите удаление. В той же карточке выберите тот же чек-лист и нажмите **Оценить**. Сервер заново проверит исходный транскрипт и сохранит новый результат.

Начальный чек-лист содержит восемь критериев из задания. Для каждого применимого критерия система умножает вес на долю набранных баллов, затем делит сумму на сумму применимых весов и умножает на 100. Итог округляется до сотых. Если применимых весов нет, итог отсутствует. Грубая ошибка сохраняется отдельным флагом.

## Режимы оценки

По умолчанию работает **CQA rules-v1** — локальный оценщик на текстовых правилах RU/KZ/EN. Он использует реплики оператора, контекст клиента и системные события. Вызов бесплатный. Эвристики могут пропускать перефразированные ответы и неверно оценивать полноту консультации. Для демонстрации нового критерия в этом режиме выберите тип «Да / Нет», отключите N/A и задайте формулировку `Оператор использует фразу «Спасибо»`. В кавычках можно указать свой текст.

Для оценки критериев со свободной формулировкой задайте в корневом `.env` значения `AI_PROVIDER=gemini`, `GEMINI_API_KEY` и `GEMINI_MODEL` и повторите команду запуска. В этом режиме транскрипт и версия чек-листа отправляются выбранной модели Google. Стоимость зависит от модели, тарифа ключа и длины переписки. В карточке оценки указаны модель и источник обработки. Для повторной проверки по тому же чек-листу нажмите «Удалить оценку», затем «Оценить».

## Результаты для сдачи

В поставку входит `results/dev/results.json` с оценками 60 чатов и пяти звонков. В подготовленной локальной базе группа `SMOKE` содержит отдельный учебный диалог с рассмотренной апелляцией для демонстрации пересчёта. Контрольный набор загружается, когда организаторы выдают его идентификатор.

Раздел **Наборы данных** поддерживает оценку всей группы и скачивание `results.json`. Для повторяемой выгрузки прямо в нужные папки есть команда для Node.js 22+ из корня проекта

```powershell
node scripts/submit.mjs --dataset dev --team Heroes
node scripts/submit.mjs --dataset prod --group ВЫДАННЫЙ_GROUP_ID --team Heroes
```

При наличии сохранённого исходного JSON добавьте `--input "путь/к/набору.json"`. Параметр `--api` меняет адрес сервера, `--checklist` выбирает версию по её UUID. По умолчанию используется официальная версия 1. **DEV** должен содержать 65 диалогов, **PROD** — 10 контрольных чатов.

Команда проверяет группу, число записей и уникальность ID, запускает оценку и записывает файл в `results/dev/results.json` или `results/prod/results.json`. Реплики в `evidence_turns` нумеруются с 1 по исходному транскрипту. Файл содержит исходные автоматические оценки, модель и отдельные записи со статусом `error` при сбоях. Код завершения 2 означает, что файл записан с ошибками отдельных диалогов. После устранения причины команду можно повторить.

## Устройство проекта

- `frontend/` — Vue 3, Vue Router, Vite. Экраны и компоненты используют относительный путь `/api`. В контейнере Nginx передаёт эти запросы в Node.js.
- `backend/` — Node.js, Express, Prisma и PostgreSQL. Здесь находятся HTTP API, миграции, импорт, проверка доказательств, расчёт баллов, апелляции и экспорт.
- `backend/ai/` — отдельный сервис оценки с локальным режимом и адаптером Gemini.
- `scripts/`, `results/` — подготовка файлов для сдачи и выгрузки.

## Проверка после изменений

В папке `frontend` выполните `npm ci`, `npm test` и `npm run build`. Чтобы подключить Vite к серверу этого Docker-проекта, в PowerShell перед `npm run dev` выполните `$env:CQA_BACKEND_URL = "http://127.0.0.1:3001"`.

В папке `backend` выполните `npm ci` и `npm run db:generate`. Для интеграционных тестов укажите в `DATABASE_URL` отдельную PostgreSQL-базу с именем `cqa_test` и учётную запись с правом её создания. Запустите `npm run db:test:prepare`, затем `npm test`. Модуль оценки проверяется отдельно командой `node --test ai/evaluator.test.mjs`.
