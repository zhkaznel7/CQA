# Фронтенд CQA

Из папки `frontend` выполните `npm ci`, затем `npm run dev`. Откройте адрес Vite в терминале. Для тестов выполните `npm test`, для статической сборки — `npm run build`. Сборка попадает в `dist/`.

## Карта проекта

- `src/app/` — оболочка приложения, навигация, маршруты и общие стили.
- `src/features/conversations/` — список диалогов и карточка с полным транскриптом. Маршрут карточки использует внутренний UUID бэкенда, пользователю показывается исходный `externalId`.
- `src/features/checklists/` — список версий. Компоненты будущего редактора размещаются здесь.
- `src/features/appeals/` — список апелляций. Участник 4 подключает здесь экран пересмотра. При интеграции существующего `js/appeals.js` и `css/appeals.css` из своей ветки сохраняет контракт `mountAppeals(container, context)`.
- `src/shared/` — клиент HTTP, состояния загрузки и ошибок, постраничный список. Предметные компоненты и операции с данными остаются внутри своей функции в `features/`.

## Подключение данных

В разработке Vite направляет запросы `/api` на `http://127.0.0.1:3000`. Запустите backend с данными отдельно. При другом порте задайте `$env:CQA_BACKEND_URL` перед запуском Vite. В статической сборке сервер размещения должен обслуживать `/api` или проксировать его. Для отдельного API задайте публичный `VITE_API_BASE_URL` перед сборкой и настройте CORS на сервере.

Навигация по хешу позволяет открывать прямые ссылки без серверных правил для путей Vue. Чтобы добавить новый экран, создайте компонент рядом с остальными файлами функции и добавьте маршрут в `src/app/routes.js`. Тесты с суффиксом `.test.js` размещайте рядом с проверяемым кодом.

## Аудиоразбор

Откройте ссылку «Открыть демозвонок с разбором аудио» в разделе диалогов или маршрут `/#/demo/audio`. Демо работает локально. Запись и границы слов находятся в `src/features/audio-review/demo/`. Времена начала слов получены от локального синтезатора речи, окончания приближённо определены по амплитуде до следующего слова. Выводы заданы вручную.

`AudioReview.vue` принимает объект `recording`. Все времена — секунды от начала того же аудиофайла, конец интервала исключён:

- `audioUrl` — доступный браузеру URL аудио. Для волны на другом домене сервер аудио должен разрешить CORS. Для длинных звонков можно передавать заранее рассчитанные пики.
- `turns[]` — `{ speaker, text, start, end, words?: [{ text, start, end }] }`. При наличии только границ реплик компонент подписывает вывод реплики целиком. Абсолютные даты звонка приводятся к позиции записи на стороне адаптера с учётом фактического начала аудио.
- `findings[]` — `{ id, criterion, explanation, start, end }`. Интервал относится к основанию конкретного вывода.

Для подключения сервера карточка диалога получает запись и реплики из существующего `GET /api/conversations/:id`, выводы — из `GET /api/evaluations/:id`. Адаптер связывает доказательства с репликами и передаёт объект в `AudioReview`. Для точной подсветки отдельных слов бэкенду потребуется передавать их интервалы. Способ выдачи этой разметки предстоит согласовать с командой.
