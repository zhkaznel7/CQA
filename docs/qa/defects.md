## BUG-001 · Импорт не принимает исходный DEV

Открыт 7 ноября 2026, T01, backend d80b03c. Если источник организатора возвращает содержимое data/dev.json, POST /api/conversations/import отвечает 502 UPSTREAM_INVALID_DATA. В тестовой базе сохранено 0 из 65 исходных ID. После адаптации структуры и имён полей импорт принимает все записи и корректно обрабатывает повтор. Влияние — требуется преобразование DEV перед импортом. Повторить T01 с исходным файлом после согласования формата на границе сервисов.

## BUG-002 · Исходная ссылка p4-ru-003 не воспроизводится в карточке

Открыт 7 ноября 2026, T14, frontend 3d44297. Открыть импортированный звонок p4-ru-003 и запустить аудио. Транскрипт доступен, но Chrome возвращает NotSupportedError. Отдельный запрос к исходному URL вернул HTTP 200 text/html. В том же плеере сохранённая копия MP3 воспроизводится с позиции 5:45. Не установлено, зависит ли ответ источника от авторизации или срока действия ссылки. Повторить со штатной ссылкой в карточке. Подписанный URL в журнал не включён.

Повтор BUG-002 на ed2b7e9: исходная ссылка возвращает страницу с audio/source, вложенный MP3 доступен. Плеер организатора воспроизвёл звонок в карточке в Chrome, перемотка на 5:45 прошла. Исправлено и проверено в codex/t14-audio-player, ожидает интеграции во frontend.

## BUG-003 · Для канала DEV «voice call» не подтверждается N/A за отсутствующее начало записи

Открыт 7 ноября 2026. Бэкенд d80b03c, отдельная копия версии v2 с правилом recording_start_missing для c1. У всех пяти звонков DEV канал записан как voice call. По сценарию синтетическая запись заведомо начинается в середине разговора. Для каждого примера в тестовую БД внесено независимое подтверждение, привязанное к диалогу, версии и c1. Отправлены одинаковые ответы mock.

| Сохранённый канал | POST /api/evaluations | Результат |
|---|---:|---|
| voice call (как в DEV) | 502 | AI_NA_UNCONFIRMED, 0 оценок в БД |
| call | 201 | Оценка сохранена, c1 = N/A |
| voice | 201 | Оценка сохранена, c1 = N/A |
| agent chat (отрицательный контроль) | 502 | AI_NA_UNCONFIRMED, 0 оценок в БД |

Версия чек-листа 1bb6e7e6-23a4-4616-9fd4-f1320f919e34, диалог для voice call 971b53c8-0f6f-4378-a0c0-a7d389e41bf0. Если при импорте сохраняется название канала из DEV, проверка N/A блокирует даже подтверждённый случай. После согласования канонического названия повторить четыре строки. Этот прогон не устанавливает, что у пяти реальных звонков отсутствует начало.

**Закрыт после независимого QA-прогона 8 ноября 2026 на backend 04dad44.** Для прежнего диалога 971b53c8-0f6f-4378-a0c0-a7d389e41bf0 и прежней версии v2 POST вернул 201, c1 = N/A, итог 38,89. GET оценки b0f95b61-c3d5-4c93-bea6-54a810136849 подтвердил сохранённую карточку. На свежих примерах voice call, voice и call без подтверждения получили 502 AI_NA_UNCONFIRMED; после подтверждения каждый получил 201, применимый вес 90 и итог 38,89. Оба чата (chat и agent chat) получили 502 в обоих случаях. После каждого отказа проверено отсутствие записей Evaluation и CriterionResult. Исходное название канала в PostgreSQL сохранено. Полный набор backend с командным HTTP mock прошёл 109/109, пропусков 0.

## BUG-004 · Офлайн-отчёт засчитывает цитату вне заявленного диапазона

Открыт 7 ноября 2026, проверка доказательств T08/T09. Бэкенд d80b03c и ai/evaluation/compare.py из 9d1e58b. В учебном диалоге клиент пишет «Добрый день.» (индекс 0), оператор отвечает «Здравствуйте, меня зовут Дана.» (1). Для c1 переданы «Да», дословная цитата оператора и верный turnIndex = 1.

| checked_range | POST /api/evaluations | Сравнение с эталоном «Да» через compare() |
|---|---|---|
| [0, 0] | 502 AI_INVALID_EVIDENCE, 0 сохранённых оценок | match, technical_issues пуст |
| [1, 1] | 201, оценка 8fa1935c-9c81-4a3a-98a6-2bc4146af639 | match, technical_issues пуст |

Реплика 1 не входит в диапазон [0, 0]. Такой сохранённый ответ может попасть в число валидных совпадений при офлайн-сравнении. Случай создан искусственно; частота в реальных предсказаниях неизвестна. До согласования валидаторов при сравнении проверять положение цитаты относительно диапазона.

**Закрыт после независимого QA-прогона 8 ноября 2026 на AI-коммите e8e1cc5.** Повторно поданы обе сохранённые фикстуры исходного дефекта. Для дословной цитаты из реплики 1 при [0, 0] отчёт дал unavailable с причиной «evidence вне checked_range», valid = 0 и matches = 0. При [1, 1] получены match, valid = 1 и matches = 1. Поведение согласуется с ранее зафиксированными ответами API. Все 12 тестов test_compare прошли. Вызовов Gemini не требовалось.
